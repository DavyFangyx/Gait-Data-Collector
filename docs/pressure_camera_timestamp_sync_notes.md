# 触觉数据与相机数据同步问题说明

## 当前实现

当前脚压帧的时间戳在 `python_app/pressure_sensor.py` 的 `parse_pressure_frame()` 中生成：

```python
captured_at=datetime.now()
```

也就是说，脚压帧时间并不是传感器硬件采样时间，也不是串口字节到达操作系统的时间，而是程序完成帧同步、校验并开始构造 `PressureFrame` 时的 PC 本地时间。

相机与脚压同步在 `python_app/recording.py` 中完成。保存压力 CSV 时，程序取 `output_id == "1"` 的相机缓存帧作为参考序列，再用脚压帧的 `captured_at` 在参考相机帧时间轴中查找位置，并按相机帧率生成 `heartbeat_id`。

关键函数：

- `_resolve_heartbeat_reference_frames()`
- `_resolve_heartbeat_frame_span()`
- `_build_heartbeat_ids()`
- `_save_pressure_output()`

## 工程风险

这种方案把脚压采样时刻近似为“软件解析完成时刻”。当系统负载较低、串口处理足够及时，这个近似可能还能工作；但在四路相机采集、图像缓存、UI 刷新、CSV/视频保存等负载存在时，脚压解析时间可能发生抖动。

可能导致的问题：

- 脚压帧实际采样时间早于 `captured_at`，延迟随系统负载变化。
- 串口缓冲区中积压的数据会被连续解析，多个历史脚压帧获得接近的 PC 时间戳。
- 与相机 1 的 `heartbeat_id` 对齐会产生漂移或局部错桶。
- 当前压力协议没有携带硬件帧号或硬件时间戳，无法从 CSV 中反推真实采样时间。

## 建议专家评估方向

1. 让脚压硬件协议携带递增帧号。
2. 如果硬件允许，增加传感器侧采样时间戳或同步计数器。
3. 在 PC 侧尽量靠近串口读取点记录 `monotonic` 到达时间，而不是解析完成后记录 `datetime.now()`。
4. 相机侧优先使用设备帧号/设备时间戳，而不是只使用 PC 接收时间。
5. 明确 `heartbeat_id` 的定义：是每 N 个相机帧一个桶，还是外部同步脉冲计数。
6. 若需要严格同步，考虑外部硬件触发/同步线，让相机与脚压采集共享同一个触发源。

## 本次未改动

本次修改只拆分了脚压串口采集与后续处理，并在录制时暂停脚压 UI 可视化。脚压帧的 `captured_at` 语义和 `heartbeat_id` 生成算法暂未改变，避免在没有硬件协议信息的情况下引入新的同步假设。
